# @deepseek-ai/dsh-client-interaction-notifications

[English](README.md) | 中文

## 概述

在应用窗口隐藏或失去焦点时，为待处理的审批、问题、计划审核和已完成任务发送静默系统提醒。随产品提供的 Web 组合为 Desktop 和浏览器启用本插件；它不改变 agent loop（智能体循环），也不回答请求。

<a id="usage"></a>
## 使用

通用设置 → **系统通知** 控制当前浏览器或设备的偏好，默认开启。浏览器用户必须点击**允许通知**授予权限；插件不会在启动时申请浏览器权限。Desktop 使用 Electron 原生通知，不会同时发送浏览器通知。在 macOS 上，首次初始化原生通知能力时，Electron 可能向系统申请授权。系统权限和勿扰模式可能阻止任一方式的提醒显示。

通知只包含应用名称和交互类别，不包含命令、路径、问题正文或会话标题。点击会恢复或聚焦 Desktop 窗口，然后通过已有导航打开所属 Session（会话）；即使 Desktop 的焦点事件先于原生点击回调到达，也不会阻止导航。浏览器点击会先请求焦点，再导航。通知不会批准操作或提交答案。导航失败继续由已有的 Conversation（对话）加载和会话不可用提示负责。

<a id="lifecycle"></a>
## 生命周期

待处理审批、问题和计划审核提醒使用当前 Client 交互登记，不是 Host 全局通知。任务完成提醒使用 Host Session 投影，不依赖选中或保留在 Client 中的 Session。纯完成投影记录 primary Session 的正常 `turn/end` 候选，排除 subagent Session。wire value 是最新候选 `SessionSeq` 或 null。实时发布还要求：没有属于该会话的运行中或停止中任务，没有已准入或尚未结算的后代 activation，没有未认领的 next-turn 或 next-step 输入。运行时所有者在事件提交时提供这些同步检查；快照、缓存恢复与历史回放从不读取实时工作状态。

Client 通过 `ISessions.onProjectionUpdate` 监听现有 root control/list 投影通道。只有实时投影帧可以触发通知；baseline/list hint、历史读取和重连 baseline 不会发出完成通知。只有投影键匹配且值等于该帧的 `seq` 时，Client 才通知，因此初始投影中携带的历史 `lastCompletedSeq` 不会被当成新完成。

取消、错误、blocked 轮次和 subagent 完成都不通知。工作结算或收件箱移除本身不会释放较早的候选；只有后续符合条件的正常 primary 轮次才可通知。运行时检查支持通知插件 HMR，不向 fork 转移工作所有权，也忽略此前 Host 进程遗留的任务记录。通知被禁用或权限不可用时，完成事件会直接消费、不排队；只有初始权限仍在加载时可以暂缓判定。

请求处理、撤销或从登记中隐藏，在前台打开其 Session，关闭提醒或卸载插件时，会撤回插件拥有的通知。其他 Session 的通知会保留。后台导航不会撤回通知。每个 Session 最多保留一条任务完成通知；后续完成会替换它。点击、关闭通知或卸载插件会关闭该通知。每次发送使用新的不透明令牌。异步发送完成较晚时，若请求已消失或所属实例已释放，则会关闭通知。卸载会等待发送与撤回完成后再释放提供者。发送失败会在通用设置中显示，不会中断待处理操作。Desktop IPC 只接受令牌、类别和语言；外壳拥有固定的通知文案。

策略与请求身份处理位于一个 Client 插件中。平台适配器拥有权限检查和显示、关闭、点击操作；增加类别需要调整请求选择和本地化文案，增加通知提供者不需要复制请求策略。

<a id="model-experience"></a>
## 模型体验

无，因为本插件不注册工具，不改变提示词，也不写入 Session 事件。

#### KV Cache 影响

无；通知不改变模型请求。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 完成投影是派生数据，现有 projection cache 可能会检查点保存；它不是新的业务事件或日志。框架可能惰性折叠 Host 内存中已有的旧日志；插件不会新增 Host 监控器、事件总线、Client 保活，也不会主动读取全部持久历史。待处理交互请求可能在刷新后或重连重建后再次提醒；仅靠工具调用身份无法区分一次调用中的多次审批。
- 属于该会话的长期服务器或监听任务会阻止完成提醒，直至其结算（包括取消）；插件不会根据模型文字推断任务是否相关。
- 离线期间错过的完成不会在之后投递。任务完成提醒仅在整个应用处于后台时发送；前台 Client 即使正在查看其他 Session，也不会收到提醒。
- 浏览器通知需要受支持的安全上下文和仍在运行的页面。关闭页面后停止提醒；不包含 Service Worker、推送投递或跨标签页协调。
- Desktop 必须仍在运行且提供通知桥接。旧版外壳显示为不支持，不会回退到浏览器通知。原生提交成功并不确认系统已显示通知，也无法读取全部系统权限设置。
- 不包含通知操作按钮、声音、重复提醒计划或聚合设置。开关仅保存在本地，不通过 Host 设置同步。
