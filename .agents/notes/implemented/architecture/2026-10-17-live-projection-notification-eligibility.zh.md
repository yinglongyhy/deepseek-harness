# Agent Note: 在投影回放之外判定实时通知资格

Status: implemented

[English](2026-10-17-live-projection-notification-eligibility.md) | 中文

## Problem

主代理的正常轮次可能在委派工作或结果投递尚未完成时结束。可继续 activation 不一定创建后台任务。持久登记可能在运行时崩溃后遗留，历史回放无法判定当前工作所有权。完成提醒不能把等待轮次或缓存中的历史完成误认为刚刚结束的任务。

## Decision

投影折叠与缓存视图保持为确定性的历史。可选同步谓词 `wire.publish(session, event)` 只控制实时视图变化的投递；否决会丢弃该次变更，不补发，也不改变快照、检查点或水位。状态同步消费者省略该谓词。它扩展而非取代[必需的投影读取接缝](2026-08-19-session-projection-mandatory-seam.zh.md)。

[完成提醒](../../../../packages/client/interaction-notifications/README.zh.md#lifecycle)在完成事件提交时读取权威任务状态、确切在线 Agent 的后代所有权及父级的两个收件箱。所有权在插件 HMR 后仍有效，且不会随复制的 fork 历史转移。仅有子级不活跃还不够，因为其结果可能仍等待父级消费。

## Alternatives considered

**在提醒投影中持久化待处理工作。** 可继续子级的重新激活需要新增持久生命周期事实，遗留任务记录还需崩溃修复。这为非持久提醒重复维护运行时所有权。

**在通知插件中跟踪观察事件。** 跟踪 activation start/end 会遗漏 HMR 前已准入的工作，也无法涵盖子级结算后排队的父级输入。

**延时或检查最终文字。** 经过的时间和模型措辞都不能确定运行时已静止。等待还会在取消或重连后产生延迟提醒。

## Consequences

不需要改变循环或 Session 事件。历史值描述轮次候选，而非运行时静止状态；只有实时变更流授权提醒。离线完成不补发。属于该会话的长期任务会保守地阻止提醒，直至结算，不以模型意图为转移。

验证覆盖不创建后台任务的实际可继续工具 activation、通知插件重载、子级不活跃后的结果投递，以及移除实时资格检查的负对照。读取和检查点恢复检查确保纯历史值保留，且不调用该谓词。
