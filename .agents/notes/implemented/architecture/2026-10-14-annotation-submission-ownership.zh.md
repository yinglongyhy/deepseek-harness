# Agent Note: 批注提交的所有权

Status: implemented

[English](2026-10-14-annotation-submission-ownership.md) | 中文

## Problem

已提交的批注包含两类数据：模型必须接收的用户文本，以及界面导航所需的结构化选区信息。准入响应丢失时，无法据此判断任一存储是否已提交。使用新的请求身份重试可能重复用户指令，而消耗当前草稿可能抹去提交后的编辑。

## Decision

[批注插件](../../../../packages/client/conversation-annotations/README.zh.md)拥有草稿和结构化旁路记录。Chat 拥有已完成文本的选区、装饰和精确源位置导航。[Composer 贡献接口](../../../../packages/client/ui-conversation/README.zh.md)在准备前冻结一次提交；批注插件不拦截所有底层发送，也不修改 Agent 循环。

引用的选区和评论成为普通用户消息文本。因此，Session 日志无需读取旁路记录，就包含完整的模型可见贡献。结构化锚点不进入 Session 事件模式，因为其用途是界面导航，而非模型上下文。

准备阶段持久化不可变尝试，但不接纳提示词。准入与旁路记录结算是独立操作。Session Controller 仅在持久化及所有者检查通过后确认准入。协调通过携带原始请求身份、属于本 Session 且非继承的用户消息或历史收件箱记录识别准入。仅有传输确认或缺少证据，都不能证明请求被拒绝。

重试保留原始请求身份和有序内容。Host 可使用保留的可信附件引用重新暂存文件传输回执；这不授权新增文本、图片、文件或贡献修订。接受仅消耗捕获的批注修订，后续编辑得以保留。

## Alternatives considered

- **跨旁路存储和 Session 准入的分布式事务。** 拒绝，因为现有两个存储均未提供共享事务。显式不确定状态和回执协调保留失败语义，而不虚构原子性保证。
- **每次连接失败后生成新的请求身份。** 拒绝，因为没有响应不等于未准入。
- **仅存于旁路记录的模型上下文。** 拒绝，因为重放和导出必须能从 Session 事件重建模型收到的用户输入。
- **将批注行为嵌入 Composer 或 Agent 循环。** 拒绝，因为这些所有者需要可复用的文本及提交接口，而不需要理解批注记录。
- **源文本变化后模糊重定位。** 拒绝，因为高亮一段看似合理但不同的文本，会歪曲用户保存的选区。

## Consequences

此功能可在浏览器生命周期之外恢复已准备的尝试，但不保证恰好执行一次。持久化准备不会保存从未准备的草稿。仅包含 Session 的复制和导出保留已提交的用户文本，却不保留结构化导航旁路记录。文件重试依赖附件字节仍被保留；批注插件不拥有附件保留策略。

可复用接口带来生命周期责任：注册随其所有者释放，重试调用方不能修改冻结尝试，结算失败保持可见且不重新接纳已接受的提示词。这些义务属于接口，而非批注专用约定。
